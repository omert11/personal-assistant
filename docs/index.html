Plugin ne yapar?

Dört ana parça.

Obsidian Proje Belleği

Klasör hiyerarşisinde saf gerçek: genel alan klasörleri (flight/, payment/, django/) tüm projeleri besler, proje klasörleri yalnız kendine özgü bilgiyi tutar. obsidian-write yazar, obsidian-search bulur. Kronoloji ve proje yapısı tutulmaz; dosya şu anki gerçeği taşır.

Commit Kalite Kapısı

commit skill, kod değişen her teslimatta /code-review'u zorunlu çalıştırır; kullanıcı "hızlıca commit" dese bile. Bulgular sorulmadan düzeltilir, commit mesajı diff'ten üretilir, yalnız teslimat şekli sorulur. Plane issue oluşturup/kapatırken self atama, başlangıç/bitiş tarihi ve hata/geliştirme label'ını otomatik doldurur.

Oturum Başı Kural Disiplini

SessionStart'ta tek çekirdek kural dosyası ~/.claude/rules/ altına kopyalanır; Django projelerinde django skill'i otomatik yüklenir. Plugin omp üzerinde de çalışır: kurallar, skill'ler ve hook'lar scripts/build-omp.py ile çevrilir.

Görsel Rapor

user-report yapılan işi tek dosyalık HTML rapora döker: ölçülmüş KPI'lar, önce/sonra grafikleri, değişim haritası. issue-workflow sonuç raporu da buradan üretilir.

core
Temel Kurallar · rules/core.md

Tüm global davranış kuralları tek dosyada, kısa maddeler hâlinde.

Kurallar
  • Emin olmadığın her konuda sor. Varsayım = hata, sormak = kalite.
  • Cevap barizse gereksiz soru sorma; en iyi seçeneği seç.
  • İletişim Türkçe; kod yorumları ve commit mesajları İngilizce.
  • Unused import, typo, formatting gibi küçük ihlaller sessizce düzeltilir.
  • Workaround yok, doğru çözüm bulunur.
  • Zorunlu olarak yarım kalan iş TODO: yorumuyla işaretlenebilir.
  • Önceki notlar obsidian-search ile aranır, yenileri obsidian-write ile eklenir.
  • Diji işi credential'ı için work-diji-secrets, kişisel işler için personal-secrets skill'i yüklenir.
  • Diji deploy, release, rollback, Dokploy, yeni site/domain, canlı env/migration veya altyapı işinde work-diji-deploy skill'i yüklenir.
  • diji sunucusundaki remote çalışma ortamı (work container'ı) hakkında bilgi gerekince remote-workspace skill'i yüklenir.
  • Tarayıcı disiplini: açılan sekme iş bitince kapatılır, tek tarayıcı örneği paylaşılır, tarayıcı testleri en fazla 2 paralel worker ile çalışır.
  • Remote ortamda kullanıcı oturumu açık tarayıcı gerekince gbrowser skill'i yüklenir.
Sub-agent

Orchestrator ve ileri teknik kod opus 5.5, diğer her şey sonnet 5.5 (medium). Çağrı model almıyorsa o modele atanmış agent kullanılır.

Genel bilgiler

Global bir kilit ağır build/test komutlarını kuyruğa alır; guard hook bunları heavy'ye sarıp arka plana atar. Obsidian vault not defteri değil, hızlı ve kesin bilgi kaynağıdır (~/Documents/ObsidianVault/).

Fayda

Kurallar her oturumda güncel ve sabit yoldan yüklenir; ayrı indeks ya da Read adımı gerekmez.

heavy-guard.sh
PreToolUse · Bash

Ağır derlemeleri makine genelindeki slot havuzuna sokar: Bash komutu ağır bir derlemeyse heavy bash -c '<komut>' olarak yeniden yazılır ve arka plana alınır; uzun ömürlü dev sunucuları heavy --low ile slotsuz, arka plan QoS'unda koşar. Paralel oturumlarda cargo + go aynı anda derlenip makineyi boğmaz.

Nasıl çalışır

stdin'deki PreToolUse payload'ı jq ile okunur. Sınıflandırma ham metne değil komut iskeletine uygulanır: heredoc gövdeleri, tırnaklı stringler ve # yorumları maskelenir (soldan sağa tek geçiş, böylece metindeki apostrof aralıkları kaydırmaz), bash -c '<komut>' içeriği ayrı aday olarak eklenir; örneğin git commit -m "perf: cargo build faster" commit'tir, derleme değil. Sonra komut ERE'lerle sınıflanır: DEV_RE (dev sunucusu) önce, sonra HEAVY_RE + PYTEST_RE (whitelist; derlemelerin yanında test koşucuları ve linter'lar da ağırdır: golangci-lint run, npm/pnpm test, pytest, manage.py test; cargo tree, go env, cargo fmt gibi anlık komutlar kasten dışarıda), en son QUEUE_RE (git commit/push). pytest ayrı desendedir çünkü tek kelimelik ad argüman olarak da geçer (grep pytest), bu yüzden yalnız komut pozisyonunda sayılır. Eşleşirse hookSpecificOutput.updatedInput ile tool_input korunarak command değiştirilir; ağır sınıfta ayrıca run_in_background: true zorlanır. Kuyruğa girebilen her sınıf (ağır + queue) timeout: 600000 alır, çünkü Bash tool'un 120 s varsayılanı HEAVY_TIMEOUT'tan kısadır ve komutu daha sırada beklerken öldürürdü. Orijinal komut jq @sh ile tırnaklanır, bileşik komutlar (&&, tırnak içeren) bozulmaz ve sarmalayıcı kabuk $SHELL'dir, sabit bash değil. macOS'un bash 3.2'si $(cat <<'EOF'…) içinde apostrof geçen heredoc'u parse edemez, yani bash -c ile sarmalamak conventional commit mesajlarını sözdizimi hatasıyla düşürürdü. Zaten heavy/lockf/taskpolicy içeren komut es geçilir. Bu kontrol komutun yalnız başında değil, başlayabildiği her yerde yapılır (cd x && heavy go test dahil); aksi hâlde dış sarmalayıcı iç heavy'nin beklediği slotu tutup kilitlenir. Desenler ~/.config/heavy/patterns.sh ile ezilebilir; eşleşme yoksa çıktı üretilmez (exit 0, passthrough).

Fayda

Hangi projede, hangi oturumda olursa olsun ağır derleme elle müdahale gerekmeden sıraya girer; dev sunucuları bloklanmaz.

commit

Kod değişikliklerini commit etmeden önce kalite kapısı kurar. Analizi sessizce yapar, bulguları sormadan düzeltir, commit mesajını diff'ten üretir; yalnız teslimat şeklini sorar (kullanıcı söylemediyse), ek soruları iş bitince sorar.

Tetikleyici

"commit", "push et", "PR oluştur", "branch aç", /commit.

Akış

status → branch tespit → teslimat sorusu → deslop (kullanıcı yüzeyi varsa) + code review (kod değiştiyse) arka planda → test (gerekiyorsa yazılır) → Plane eşleştir → Obsidian → bulgular düzeltilir → otomatik mesajlı commit (Co-Authored-By) → teslimat → Plane otomatik kapat/oluştur → son sorular (Obsidian, worktree) → sonuç özeti.

Öne çıkan

Code review kod değiştiyse zorunlu, tek tur ve tek seviye: claude -p '/code-review low' ayrı oturumda arka planda; büyük diff modül bazlı 3-4 paralel oturuma bölünür. Tüm bulgular (uncertain dahil) düzeltilir. Yasaklar ayrı bölümde: git add -A, --no-verify, --amend, ana branch'e force push, bulgu filtrelemek.

django

Diji Django projeleri için zorunlu kurallar: CSRF ve full-page cache uyumu, F7 çeviri domain'i (djangof7), uv ile proje kurulumu, mobil publish öncesi domain pre-flight, proje yapısı ve deploy tetikleyicisi (PR merge → release-bot tag + Dokploy deploy).

Tetikleyici

Django projesinde çalışırken (template/form/AJAX/CSRF, makemessages, kurulum, mobil release, deploy). manage.py olan projelerde django-detect.sh hook'u skill'i oturum başında otomatik yükler.

obsidian-write

Kalıcı bilgi/kararı vault'a yazar. Konumlandırma (genel alan mı proje mi), saf gerçek formatı ve arama yüzeyi kuralları bu skill'de tanımlı. Ana agent yazar, subagent devri yok: devirde teknik kesinlik (parametre adı, limit değeri, hata metni) prompt serileştirmesinde kaybolur.

Tetikleyici

"obsidian'a yaz", "bunu kaydet", "vault'a ekle", /obsidian-write. commit skill'in Obsidian sorusu da buraya yönlendirir.

11 adımlı self-check

Noktaları ayrıştır (kaç bilgi/karar var, kalıcı mı) → her nokta için ayrı döngü: genel mi proje mi → kategori/yol → saf öğreti cümlesi → zaman-bağlı ifade temizliği → vault'ta var mı (istisnasız bak) → varsa düzelt, yeterliyse yazma → bulunamadıysa arama stratejisini kullanıcıya bildir → tekrarı ortaklaştır → 6 ay sonra hangi terimle ararım → dosya hâlâ saf mı.

Öne çıkan

Bug yazılmaz, nihai öğretiye dönüştürülür: "hash açığı vardı, kapatıldı" değil → "ödeme HashParamsVal ile doğrulanmalı". Kanıt (ticket/PNR/commit), hikâye ve kronoloji yazılmaz; dosya şu anki gerçeği taşır. Frontmatter yalnız tags+aliases (arama yüzeyi); date/confidence/source bayatladığı için yazılmaz. Credential tam yazılır (vault lokal dosya sistemi).

Tetikleyici

Akış

Öne çıkan

Genel alan (flight/, django/) ile proje klasörü birbirini tamamlar, ikisine de bakılır. Sıfır sonuç konunun henüz yazılmadığını gösterir; bu durum raporlanır, konu iş bitince yazılır.

log-triage

Bir diji-logs projesinin son N saatlik logunu zaman pencerelerine böler, her pencereyi çok açıdan paralel analiz eder, bulguları doğrular ve onayla Plane'e issue açar. Proje-bağımsızdır; değişen tek şey hedef proje ve Plane proje UUID'si.

Tetikleyici

"logları analiz et", "son N saatte sorun var mı", "log triage", "loglardan issue çıkar", /log-triage <proje> <süre>.

Akış

fetch_windows.sh ile pencereleri stratified çek (ERROR/WARN ham + DEBUG/SQL aggregate) → tek fazda pencere×açı paralel sub-agent → dedup + canlı sorgu ile doğrula → 4 katmanlı tablo sun → log-triage label'ı ile Plane eşleştir → katman katman onay → sırayla issue aç.

Öne çıkan

4 standart açı (hata / perf / akış / hijyen) her pencerede paralel taranır. Sahte ERROR (ErrRecordNotFound) ayıklanır, PII/credential sızıntısı işaretlenir. Her issue ≥1 ham log örneği + provenance taşır (sonraki oturum sıfırdan kazmasın). Issue açma sub-agent'a devredilmez: HTML escape için Claude sırayla açar.

issue-workflow

Bir kaynağı (Plane issue / serbest metin / doküman / görsel / log) uçtan uca çözer: tam bağlam çıkarır → kök-neden analizi → izole worktree + plan → çözüm + kanıt → commit skill → sonuç raporu. Duraklamasız tek akış: adımlar arasında onay/kapı yok; yalnız gerçekten belirsiz bir karar veya sert durakta soru sorulur. En doğru yolu agent kendisi belirler.

Tetikleyici

"şu ticket'i çöz", "bu hatayı worktree'de çöz", "ticket analiz et ve düzelt", "şu dokümandaki sorunu hallet", /issue-workflow <ref|metin>.

Akış
  • 1: AGENTS.md "## Issue Workflow" alanını oku (proje-özel komut/port/test/akış notu)
  • 2: kaynak toplama, tam detay (Plane, metin, görsel, doküman, log)
  • 3: analiz (ultrathink); şu anki durum / istek / neden / yapılacaklar / öneriler / açık konular (en iyisi seçilir, yalnız belirsizse sorulur) / riskler
  • 4: uygulama modu sormadan seçilir: kullanıcı söylediyse veya 2+ sinyal varsa (ayrık görevler, sıralı bağlılık, büyük boyut) yönetici modu (references/yonetici-modu.md, Adım 7 yerine 7Y), değilse tek akış
  • 5: worktree aç (EnterWorktree; SESSION_NAME = worktree ismi) + plan context'te kurulur, onay beklenmeden uygulanır
  • 6: kaynak Plane issue ise işleme al (otomatik): started + assignee yoksa self ata + start_date boşsa bugün; dolu/zaten started olana dokunma
  • 7: uygula ([SESSION_NAME] prefix'li loglar) → test ortamı → unique port + arka plan → kanıt /tmp/issue-<isim>/ (görselde screenshot zorunlu) → uygulamayı durdur (yönetici modu → 7Y: sub-agent dalgaları, ilk dalga sözleşme, doğrulama + fix + kanıt sonda)
  • 8: [SESSION_NAME] log temizliği (bloklayıcı)
  • 9: commit skill: akışın tek review noktası + tek commit + tek PR + Plane kapama
  • 10: user-report ile HTML sonuç raporu (kararlar, gömülü kanıtlar, ek kazançlar, son durum, commit/PR/Plane), tarayıcıda açılır
Öne çıkan

Kontrol sonda, tek seferde yapılır. Ara commit, ara build, ara review, aşamalı teslim yapılmaz; süreç içinde kırık noktalar normaldir. Tek PR açılır. Kanıt dosyaları repo dışında (/tmp/issue-<isim>/) tutulur.

deslop

Metindeki AI yazım izlerini (slop) son kullanıcının gördüğü yüzeylerde temizler. Yönetici/işçi ayrımı üzerine kurulu: /deslop oturumu kuralları okumaz ve bilmez, tek bir dosyanın bile içeriğine bakmaz; Grep/Glob tool'ları verilmemiştir. Tek find / git status komutuyla düz yol listesi alır, dizin sınırından gruplara böler (grup başına dosya limiti yok), her grubu ayrı claude -p oturumuna verir, dönen raporları birleştirip git diff ile doğrular. Kural bilgisi, kapsam analizi ve düzenleme yetkisi yalnızca do-deslop oturumundadır; kural iskeleti + canlı kaynaklar + dosya içerikleri birlikte yüz binlerce karakterdir ve ana context'te tutulması sonraki işleri bozar.

Tetikleyici

"slop temizle", "AI izlerini temizle", "metni insanlaştır", /deslop, /deslop ./*, /deslop README.md docs/index.html. Argümansız çağrı git değişikliklerini tarar; repo geneli açık istek olmadan açılmaz. Ayrıca commit skill'i adım 3b'de zorunlu olarak çağırır (diff'te kullanıcı yüzeyi varsa), code review ile aynı anda arka planda.

Akış

repo kökü → tek komutla ham yol listesi (argüman → kabuk glob + find; argümansız → git status) → yalnız mekanik eleme (node_modules/dist/.git, lock/minified, >1 MB, binary tespiti grep -Il '' ile; boyut eşiği -size -1024k, BSD find -1M'i yukarı yuvarlayıp listeyi sessizce boşaltır) → >40 dosyada hacim kapısı → dizin bazlı gruplar (dosya limiti yok), aynı anda ≤6 oturum, kalanlar dalgalar hâlinde → cd <repo> && claude -p '/personal-assistant:do-deslop <paths>' (arka planda, timeout 600000) → git diff ile doğrula → birleşik rapor + bırak/geri al sorusu.

Öne çıkan

Hiçbir grup, hiçbir dosya atlanmaz: grup sayısı taşarsa eşzamanlılık artırılmaz, dalga eklenir; grup içinde de örnekleme/kırpma yapılmaz, kesilen oturumun işlenmemiş dosyaları yeniden gönderilir. Kapsam kararı do-deslop'ta: AGENTS.md, rules/, test, config, .py dahil her dosya listede kalır ve gönderilir; kapsam dışı olanlar için do-deslop SKIPPED döner. Alt oturumun raporu kanıt değildir: CHANGED dosyaları diff'te doğrulanır, CLEAN dediğinde beklenmedik değişiklik varsa hunk geri alınır. SOURCES: FAILED dönen grup yapılmamış sayılır ve tekrar koşar. Commit bu skill'de yapılmaz; teslimat commit skill'inin işidir.

deslop işçisi · elle çağrılmaz

Verilen dosyalarda AI yazım izlerini canlı kaynaktan okuyup tek tek temizler. Kural iskeleti (references/ai-writing-rules.md) kelime listesi tutmaz. Kelimeler, swap tabloları, dönem/model imzaları ve sayısal eşikler eskidiği için her koşuda upstream'den okunur: Wikipedia Signs of AI writing (kelime sınıflandırmasında kazanan otorite), jooray/humanizer, haidrrrry/humanize-ai-writing (ai-tells + rewrite-rules + checklist), bharvey2026/humanise-skill, jalaalrd/anti-ai-slop-writing. scripts/deslop-sources.sh bunları 24 saatlik TTL ile ~/.cache/deslop-sources/ altına atomik yazar; paralel oturumlar aynı önbelleği paylaşır. Zorunlu bir kaynak çekilemezse iş yapılmaz; kurallar hatırlanarak uygulanmaz.

Tetikleyici

/do-deslop <dosya|glob|dizin>...: yalnız deslop skill'inin açtığı ayrı claude -p oturumunda. Normal sohbette elle çağrılmaz (disable-model-invocation).

Kapsam

Yalnız son kullanıcının gördüğü yüzey. Tam dosya: README/docs .md, landing HTML, template (jinja/twig/blade/erb), .po (yalnız msgstr), i18n JSON/YAML değerleri, e-posta şablonu, store metni. Kısmi: kaynak koddaki UI string literal'ları (t()/gettext(), toast, form label/placeholder/help_text, Django verbose_name). Asla: kod mantığı, kod yorumu/docstring, test, config, AGENTS.md/SKILL.md/rules, CHANGELOG, fenced code block, link hedefi, HTML attribute ve <script>, msgid, i18n anahtarları.

Öne çıkan

Toplu değiştirme yasak. sed -i/awk/perl -pi çalıştırılmaz, Edit'te replace_all kullanılmaz, çünkü aynı kelime bir cümlede iz, başka cümlede doğru kelimedir. Her dosya baştan sona okunur (grep ile ilgili yere atlama yok; bağlam tam metinden gelir, context kaygısı bu oturumda yoktur) ve her düzeltme ayrı bir Edit çağrısıdır. Karar kümelenmeye dayanır, tek işaret tek başına düzeltme gerekçesi değildir; yanlış pozitif listesi (em dash, kıvrık tırnak, resmî kelime dağarcığı, kusursuz dilbilgisi) korunur. Olgu/isim/sayı/tarih/atıf eklenmez ve değişmez; .po'da format belirteçleri (%s, {count}) ve çoğul sırası birebir kalır. Rapor birebir alıntı ister, yüzde/olasılık skoru üretmez.

user-report

Yapılan işi veya bir konuyu tek dosyalık, görsel zengin HTML rapor olarak sunar. Saf ölçülmüş gerçek, tek bakışta özet: KPI kutuları, önce/sonra grafikleri, renkli değişim haritası, akış çipleri, diyagramlar.

Tetikleyici

"rapor hazırla", "görsel özet", "yaptıklarımızı özetle", "önce/sonra göster", /user-report.

Öne çıkan

Tek dosya /tmp/<konu>.html, CDN kütüphaneleri (Tailwind, Chart.js, Mermaid, Lucide); server gerekmez. Headless tarayıcıda render doğrulanır, sonra kullanıcının tarayıcısında açılır.

user-message

Müşteri/acenta tarafına kanal-agnostik mesaj üretir (ticket/email/panel/WhatsApp/SMS/push). Stil rehberini her çalıştırmada okur, onaya sunar, revize gelirse hem düzeltir hem stil dosyasına öğrenim işler.

Tetikleyici

"müşteri mesajı yaz", "acentaya mesaj", "plane yorumu", "duyuru yaz", "whatsapp mesajı", "sms yaz".

Akış

Stil rehberini oku (yoksa dur) → kanal belirle → bağlam topla → mesaj üret → onay → revize ise yeniden üret + stil dosyasına ders ekle.

Öne çıkan

E-posta kanalı zengin HTML üretir (vurgulu tablo, kalın, liste) ve sistem varsayılan programıyla (open) açıp AskUserQuestion ile onay alır; diğer kanallar düz metin + zed --wait. Stil dosyası tek doğruluk kaynağı (bellekten yazmaz). Her revize stil dosyasına kalıcı ders olarak işlenir. Türkçe karakter ASCII karşılığı (s/sh) yasak.

full-translation
çeviri ajanları: sonnet

Django projesinde tüm dillerin eksik/fuzzy çevirilerini uçtan uca tamamlar: makemessages → po-cli analyze → entry yüküne göre çeviri → apply → compilemessages → commit. po-cli skill tek .po dosyası için; bu skill çok dil × çok domain (django/djangojs/djangof7) matrisini orkestre eder.

Tetikleyici

"tam çeviri akışı", "tüm dilleri çevir", "i18n sync", "translation workflow", /full-translation.

Akış (7 adım)

Repo + mobil pull (koşulsuz zorunlu: mobil HEAD=origin/main doğrulanmadan Adım 1'e geçilmez; atlanırsa F7 metinleri sahte "0 untranslated" verir) → makemessages (3 domain) → po-cli --json analyze → iş birimi = entry sayısı: toplam ≤200 ise inline (sub-agent yok), >200 ise dil sınırında ~200'lük chunk'lara bölünüp chunk başına 1 paralel sub-agent → dry-run validate + tek onay + apply + perl temizlik → compilemessages + re-analyze (yakınsama) → commit skill. Çeviri yoksa bile derle & gönder: hiç untranslated/fuzzy çıkmasa dahi makemessages .po'yu yeniden formatladıysa (line-wrap/header/kaynak konum) compile + commit atlanmaz; .mo tracked ve runtime okunur, .po ile senkron kalmalı. Sadece .po diff'i tamamen boşsa akış temiz sonlanır.

Öne çıkan

Fuzzy msgstr'ye güvenmez (msgid'den sıfırdan), placeholder/slug/marka kuralları ajan prompt'una gömülü, plural (nplurals) tablosu dile göre. po-cli'yi tekrar etmez, ona dayanır. Kapalı diller çevrilmez: HIDDEN_LANGUAGES (örn. djangomain/app_options.py) dinamik tespit edilir, analiz + çeviri + yakınsama matrisinden çıkarılır. Kapalı dile token harcanmaz; "tüm diller temiz" kriteri hidden hariç değerlendirilir.

web-scrape-cleaner
model: haiku

Ham scrape markdown'ındaki gürültüyü temizler (nav/footer/cookie banner/reklam, boş başlık, link gürültüsü). Tools: Read/Edit/Write/Glob/Grep/Bash.

Nasıl çalışır

Keşif (örnek dosyada gürültü tespit) → tüm dosyaları concat + uniq -c ile 5+ dosyada tekrar eden satırları sil → aggressive/conservative temizleme → fark >%5 ise üstüne yaz (orijinal silinmez) → başlık hiyerarşisi + link sadeleştirme.

Öne çıkan

Asla scrape etmez (sadece mevcut .md düzenler), asla git commit yapmaz, KEEP listesine dokunmaz. İstenirse .original/ yedeği bırakır.

Bağımlılıklar · dış araçlar

Plugin neye dayanıyor?

Plugin kendi başına çalışır. setup.sh hepsini tek komutla kurar; her araç opsiyoneldir; araç yoksa ilgili özellik sessizce devre dışı kalır.

setup.sh + setup.py
Tek komutla kurulum

Tüm stack'i tek komutla kuran idempotent installer. setup.sh önce uv yoksa kurar, sonra setup.py'yi rich/questionary bağımlılıklarıyla ephemeral venv'de çalıştırır (global kirletmeden).

Ne kurar

settings.json + statusline, Homebrew prerequisites, Python CLI araçları (uv tool), Obsidian vault + CLI, local MCP repo'ları, plane-cli, po-cli, Playwright CLI, playwright-best-practices skill'i, Context7 CLI, Claude Code MCP server'ları ve interaktif credential prompt'ları.

Çalıştırma
./setup.sh              # uv kurup başlatır
# idempotent — tekrar çalıştırılabilir, mevcut olanı atlar
Obsidian
vault · bilgi tabanı

Nedir: Markdown tabanlı yerel bilgi tabanı; dosyalar [[wikilink]] ile birbirine bağlanır. Vault düz dosya sistemidir, uygulama açık olmadan da okunur/yazılır. Resmi CLI (obsidian komutu) BM25 arama ekler, zorunlu değildir.

Ne işe yarar: Kalıcı teknik gerçeği (sistem davranışı, kalıcı karar, credential) oturumlar arası taşır. Genel alan klasörleri tüm projeleri besler; proje klasörü yalnız kendine özgü olanı tutar.

Plugin'deki rolü

3 skill (obsidian-search/obsidian-write/obsidian-doc-source) doğrudan Obsidian üzerine kurulu; hepsi ana agent context'inde çalışır, subagent yoktur. Vault ~/Documents/ObsidianVault/ altında klasör hiyerarşisidir (genel alan + proje); MOC/index.md kullanılmaz. Erişim Glob/Grep/Read ile, Obsidian CLI opsiyonel.

Plane
plane-cli · proje/issue yönetimi

Nedir: Açık kaynak, self-hosted bir proje/issue yönetim aracı (Jira/Linear alternatifi). Plugin plane-cli binary'si üzerinden REST API'sine bağlanır.

Ne işe yarar: Issue/project/cycle/module listeleme, oluşturma, state güncelleme, atama ve yorum. İş takibi terminalden çıkmadan yapılır.

Plugin'deki rolü

Opsiyonel: AGENTS.md'de Plane proje UUID tanımlıysa commit skill'i değişiklikle uyuşan issue'yu completed state'e çekebilir. Tanımlı değilse Claude native TaskCreate ile takip yeterli.

Yapılandırma
~/.zshrc → PLANE_URL + PLANE_API_KEY + PLANE_WORKSPACE_SLUG
AGENTS.md → Plane proje UUID (opsiyonel)
Solo
CLI · process yönetimi

Nedir: Geliştirme process'lerini (backend, frontend, worker vb.) yöneten bir araç; solo.yml ile tanımlanan komutları başlatır, durdurur, yeniden başlatır ve çıktılarını takip eder. solo CLI binary'si Solo app'in HTTP control plane'ine bağlanır (solo doctor ile doğrulanır).

Ne işe yarar: Tekrar eden shell komutlarını (build + run) tek yerde toplayıp Claude'un bunları başlatıp loglarını okumasını sağlar.

Plugin'deki rolü

Tekrar eden komutlar solo.yml'a toplanıp Solo üzerinden çalıştırılabilir. Process başlatma/durdurma/restart solo processes / solo commands CLI komutlarıyla yapılır; process çıktısı/logu solo processes output ile CLI'den okunur.

WhatsApp
whatsapp-mcp · mesaj kanalı

Nedir: WhatsApp Web bridge'i üzerinden mesaj gönderme/okuma sağlayan bir MCP server (whatsapp-mcp, stdio). QR kod okutulup bridge başlatılarak bağlanır.

Ne işe yarar: Sohbetleri listeleme, mesaj arama, kişi bulma ve mesaj/dosya/ses gönderme.

Plugin'deki rolü

user-message skill'inin çıktı kanallarından biri. Skill müşteri/acenta mesajını kanal-agnostik üretir; WhatsApp seçilirse mcp__whatsapp__* araçlarıyla gönderilir (skill mesajı üretir, gönderimi entegrasyon yapar).

Google Workspace
Gmail · Calendar · Drive (claude.ai MCP)

Nedir: claude.ai üzerinden sağlanan resmi Google MCP server'ları: Gmail (e-posta), Google Calendar (takvim) ve Google Drive (dosya). HTTP MCP olarak bağlanır, OAuth ile yetkilendirilir.

Ne işe yarar: E-postaları okuma/arama/gönderme, takvim etkinliklerini görüntüleme/oluşturma ve Drive dosyalarına erişim.

Plugin'deki rolü

user-message skill'inin e-posta kanalı Gmail ile gönderilebilir; takvim/dosya entegrasyonu genel asistan akışlarını besler. Üç servis de claude.ai üzerinden gelir, ayrı binary kurulumu gerekmez.

Yetkilendirme
Claude Code → /mcp → claude.ai servisi seç → Authenticate
# Gmail / Google Calendar / Google Drive ayrı ayrı OAuth
Diğer Araçlar
opsiyonel destekleyiciler

Plugin ayrıca şu araçlarla entegre olur (hepsi opsiyonel, setup.sh kurar):

Destekleyici stack
  • uv: Python paket/script yöneticisi; setup.py, crawl2md ve tüm Python akışlarının temeli.
  • Playwright CLI: tarayıcı otomasyonu ve frontend testi (playwright-cli skill'i; MCP yerine CLI).
  • playwright-best-practices: @playwright/test ile E2E/component/API/visual spec yazımı için harici skill (currents.dev, MIT); ~/.claude/skills/ altına klonlanır. playwright-cli skill'i tarafından zorunlu eşlikçi olarak çağrılır.
  • Context7 (ctx7): kütüphane/framework dokümanını canlı çeker; obsidian-doc-source library modunda zorunlu.
  • Plane (plane-cli): proje/issue yönetimi; user-message ile issue yanıtı üretimi.
  • markitdown: PDF/Office/ses/görsel → markdown; crawl2md ve obsidian-doc-source dosya kaynaklarında.
