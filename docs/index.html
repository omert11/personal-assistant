Plugin ne yapar?

Detaylara inmeden önce, plugin'in en güçlü yetenekleri.

Obsidian Proje Belleği

Klasör hiyerarşisinde saf gerçek: genel alan klasörleri (flight/, payment/, django/) tüm projeleri besler, proje klasörleri yalnız kendine özgü bilgiyi tutar. obsidian-write yazar, obsidian-search bulur. Kronoloji ve proje yapısı tutulmaz — dosya şu anki gerçeği taşır.

Commit Kalite Kapısı

commit skill, kod değişen her teslimatta /code-review'u zorunlu çalıştırır — "hızlıca commit" dense bile. Dürüst review, hiçbir bulgu gizlenemez; soruları biriktirip tek onayla teslim eder. Plane issue oluşturup/kapatırken self atama, başlangıç/bitiş tarihi ve hata/geliştirme label'ını otomatik doldurur.

Oturum Başı Kural Disiplini

SessionStart'ta 15 global kural materialise edilir. Claude her oturumda tutarlı kurallarla çalışır: uv zorunlu, AskUserQuestion zorunlu, vault erişimi ana agent'ta, commit skill zorunlu.

Extension Builder

Claude Code'un 8 genişletme tipini (skill/plugin/agent/hook/MCP/output-style/channel/marketplace) resmi dökümanı WebFetch ile canlı çekerek üretir — schema uydurmaz.

Rules · 15 global kural

Her oturumda yüklenen davranış disiplini

load-rules.sh hook'u bu kuralları ~/.claude/rules/ altına materialise eder. Her biri Claude'un nasıl davranacağını belirler.

ask-first
Önce Sor

Kullanıcıya yöneltilen her soru, seçim veya onay düz metinle değil, yalnızca AskUserQuestion tool çağrısıyla sorulur. Düz metin soru tamamen yasaktır.

Kural mutlaktır: tek bir evet/hayır onayı bile ("devam edeyim mi?" gibi tek satır metin yasak — yerine ["Evet","Hayır"] tool çağrısı); commit/destructive/geri-alınamaz onaylarda metinle "onaylıyor musun?" yasak; çoklu seçenekte markdown 1. 2. 3. liste yasak. Felsefe: varsayım = hata, sormak = kalite; çelişki görünce sor, bilgi eksikse tahmin etme.

Self-Check

Metne ? yazmadan önce dur: (1) kullanıcıya soru mu? → AskUserQuestion; (2) "A mı B mi?" fragment yasak; (3) "onaylıyor musun" formları hep tool. Önerilen seçenek ilk sırada (Recommended) etiketiyle.

coding
Kod Disiplini

İletişim Türkçe, kod yorumları ve commit mesajları İngilizce. Küçük ihlaller sessizce düzeltilir, mimari ihlaller durdurularak raporlanır.

Proaktif hijyen: unused import, typo, formatting sessizce düzeltilir; mimari ihlal (güvenlik açığı, yanlış pattern) görülürse işlem DURDURULUR ve AskUserQuestion ile raporlanır. Otonom çözüm: hata verildiğinde yönlendirme beklenmez. Geçici çözüm (workaround) yerine doğru çözüm bulunur. Hatalar her zaman wrap edilir.

workflow
Görev Takibi + Goal + Subagent + Background

Çok adımlı işte görevler TaskCreate/TaskUpdate ile canlı takip edilir; subagent/workflow task zorluğuna göre serbest — ama iş delegasyondan önce kesinleştirilir ve çıktı doğrulanır.

Görev takibi: 3+ adım / çok dosya / planlı akış başlayınca TaskCreate ile görev listesi açılır ve süreç boyunca canlı tutulur — kullanıcı akışın nerede olduğunu görsün, hiçbir adım unutulmasın.

Subagent/workflow — üç keskin şart: (1) delegasyondan önce iş kesinleştirilir — girdi, kapsam sınırı, beklenen çıktı formatı ve "ne yapılmayacak" prompt'a net yazılır, muğlak tanımla agent çağırmak yasak; (2) gereksiz kontrol önlenir — çıktıyı ana agent doğrulayacaksa subagent'a "review/test yapma, kontrol bende" sınırı konur; (3) çıktıya "doğru değilmiş" gözüyle bakılır — iddialar kendin teyit edilir, parçalar çelişki ayıklanarak birleştirilir, doğrulanamayan şey doğrulanmış gibi raporlanmaz.

Çalıştırma: bloklamayan işler varken bloklayan komut background'a alınır (subagent, uzun Bash, workflow); açık kalması gerekmeyen her Bash komutuna timeout konur.

obsidian
Bellek Kullanımı

Vault, hızlı ve kesin bilgi erişim kaynağıdır — not defteri veya geçmiş kaydı değil.

Yalnız iki tip yazılır: bilgi (sistem/servis gerçekte nasıl çalışıyor, credential dahil) ve karar. Bug'ın kendisi değil nihai öğretisi. Yapı klasör hiyerarşisidir (<alan>/ genel + <proje>/<modül>/), max 3 seviye; index.md/MOC kullanılmaz — klasör zaten haritadır (tek istisna docs/: dış kaynak dokümantasyonunun bölüm listesi). Erişim Glob/Grep/Read ile doğrudan filesystem'den; Obsidian CLI opsiyonel BM25 tamamlayıcısıdır.

Karar

Obsidian → teknik gerçek (proje veya alan geneli) · ~/.claude/memory/ → kullanıcı profili · ~/.claude/rules/ → tüm projeler. Subagent yok: arama/yazma ana agent context'inde.

token-efficiency
Model Ekonomisi

Subagent ve Workflow ajanlarında model her zaman bilinçli seçilir — en küçük yeterli model.

Agent frontmatter'ına her zaman açık model: yazılır (haiku/sonnet/opus/fable, tam ID veya inherit); workflow agent() çağrılarında opts.model açıkça belirtilir. Mutlak kural — sub/agent fable YASAK: hiçbir workflow agent() çağrısı veya subagent fable ile çalıştırılmaz; fable oturumunda opts.model boş bırakmak fable'ı devralır, bu yüzden her çağrıya açık model yazılır (en yükseği opus). Hazır/named workflow'lar (Workflow({name: ...})) model override taşımadığından fable oturumunda doğrudan launch edilmez — script kopyasına her agent() için açık model yazılıp scriptPath ile çalıştırılır (mekanik/finder sonnet, derin verify/judge opus); kopya mümkün değilse launch edilmez, kullanıcıya sorulur. Code review — tek kural: agent /code-review skill'ini doğrudan çağıramaz; code-review'i tetikleyen her yer (commit, issue-workflow, ad-hoc) aynı komutu kullanır — arka planda cd <çalışma-klasörü> && claude --model opus --effort <effort> -p '/code-review <level>'. Subagent spawn edilmez, Workflow launch edilmez. Seviye dört kademelidir — 1: --effort low + review low (çok basit, mekanik), 2: --effort medium + review low (basit), 3 (varsayılan): --effort low + review medium (normal iş), 4: --effort medium + review medium (çok karmaşık: çok modül, mimari/güvenlik). Agent gerekçesiz yükseltmez; high+ yalnızca kullanıcı isterse. Büyük diff'te review bölünür: değişen dosyalar örtüşmeyen kümelere ayrılıp 3-4 paralel claude -p oturumu koşar (yol hâlâ ayrı oturum — subagent/Workflow değil), bulgular birleştirilip dedup edilir. Effort de model kadar önemlidir: her agent() çağrısına açık effort yazılır — boş bırakılırsa ajan oturumun effort'unu devralır, yani effort: max ile koşan bir skill'de mekanik bir ajan bile max düşünür. Eşik: mimari tasarım / imza-şema üretimi / derin verify high, sıradan kod-çeviri-fix medium, mekanik ve salt-okunur iş low.

Örnek
agent(prompt, { label: 'translate:ar', model: 'sonnet', effort: 'low', schema })

heavy-build
Derleme Slotu

Ağır derlemeler proje ve dil fark etmeksizin ortak bir slot havuzundan geçer (varsayılan 2 eşzamanlı) — paralel oturumlarda CPU/bellek sıkışması biter.

heavy <komut> ortak slot havuzundan boş bir slot alır; lockf tek dosya kilitlediği için N slot = N kilit dosyasıdır (~/.cache/heavy-build.lock.<n>), round-robin denenir. Varsayılan HEAVY_SLOTS=2: iki derleme paralel koşar, üçüncüsü slotları tutan komut+pid ekrana yazılıp bekler (tavan HEAVY_TIMEOUT, varsayılan 1200 s; aşılırsa komut çalıştırılmaz, rc=75). Komutun kendi 75'i "slot dolu" ile karışmaz — iç sarmalayıcı 175'e çevirir, yoksa komut ikinci kez koşardı. Uzun ömürlü dev sunucuları (cargo tauri dev, air, runserver) slot almaz — heavy --low ile taskpolicy -b arka plan QoS'una alınır, aksi hâlde slotu saatlerce tutup guard'ın kendisi tıkanma sebebi olurdu. Üçüncü bir mod heavy --queue: slot bekler ama tavan dolunca komutu slotsuz yine çalıştırır — git commit ve git push bu moda girer. Sebep: guard yalnız Claude'un yazdığı komutu görür, onun tetiklediği git hook'larını değil — pre-commit linter koşturur, lefthook pre-push cargo test başlatır ve bu derlemeler slot havuzunun tamamen dışında kalır. Hook'u tetikleyen git fiili slotu onlar adına alır, ama --queue sayesinde commit/push hiçbir koşulda bloke olmaz. heavy --status dolu slotların yanında kuyrukta bekleyenleri de listeler (mod, bekleme süresi, pid, cwd, komut); slot alınınca kayıt düşer, ölmüş bekleyenin artığı süpürülür. Slot tutan bir komutun içinden heavy çağrılırsa iç çağrı mevcut slotu kullanır (HEAVY_SLOT_HELD) — aksi hâlde dış heavy, iç heavy'sinin beklediği slotu tutar ve tek slotlu makinede kilitlenir. Her slotlu koşu ~/.cache/heavy-build.log'a tek satır yazar (mod, slot sayısı, bekleme, çalışma, rc, load, cwd, komut; secret'lar maskeli, dosya 600, 512 KB'da kırpılır) ve heavy --stats bunu özetler — kaç koşu kuyrukta bekledi, bekleme/çalışma oranı, ortalama load. Yüke göre dinamik slot sayısı bilinçli olarak yapılmadı: bu makinede load 18.47 iken CPU %46 idle ölçüldü (darboğaz I/O ve bellekti, CPU değil), açılan slot geri alınamadığı için karar salınır, kazanç ise yalnız "makine boş + kuyrukta iş var" anında doğar. Önce --stats verisi biriktirilecek. Makine-lokal ayar ~/.config/heavy/config.sh ile verilir (HEAVY_SLOTS/HEAVY_TIMEOUT/HEAVY_STATE_DIR; plugin güncellemesi ezmez, komut satırındaki env her zaman üstün gelir) — az bellekli makinede tek slota düşmek için repo varsayılanını değiştirmek gerekmez. Dosya alt kabukta okunur: bozuk bir config uyarı verip varsayılana düşer, yoksa guard her derlemeyi arka planda sarmaladığı için bir typo tüm build'leri sessiz no-op'a çevirirdi. Uygulama iki katmanda: heavy-guard.sh PreToolUse hook'u (otomatik) ve solo.yml komutları (elle). PATH shim bilinçli kurulmadı — cargo tree/go env gibi anlık komutları da yakalayıp kırılganlık üretiyor.

heavy-guard.sh
PreToolUse · Bash

Ağır derlemeleri makine genelindeki slot havuzuna sokar: Bash komutu ağır bir derlemeyse heavy bash -c '<komut>' olarak yeniden yazılır ve arka plana alınır; uzun ömürlü dev sunucuları heavy --low ile slotsuz, arka plan QoS'unda koşar. Paralel oturumlarda cargo + go aynı anda derlenip makineyi boğmaz.

Nasıl çalışır

stdin'deki PreToolUse payload'ı jq ile okunur. Sınıflandırma ham metne değil komut iskeletine uygulanır: heredoc gövdeleri, tırnaklı stringler ve # yorumları maskelenir (soldan sağa tek geçiş, böylece metindeki apostrof aralıkları kaydırmaz), bash -c '<komut>' içeriği ayrı aday olarak eklenir — git commit -m "perf: cargo build faster" commit'tir, derleme değil. Sonra komut ERE'lerle sınıflanır: DEV_RE (dev sunucusu) önce, sonra HEAVY_RE + PYTEST_RE (whitelist — derlemelerin yanında test koşucuları ve linter'lar da ağırdır: golangci-lint run, npm/pnpm test, pytest, manage.py test; cargo tree, go env, cargo fmt gibi anlık komutlar kasten dışarıda), en son QUEUE_RE (git commit/push). pytest ayrı desendedir çünkü tek kelimelik ad argüman olarak da geçer (grep pytest) — yalnız komut pozisyonunda sayılır. Eşleşirse hookSpecificOutput.updatedInput ile tool_input korunarak command değiştirilir; ağır sınıfta ayrıca run_in_background: true zorlanır. Kuyruğa girebilen her sınıf (ağır + queue) timeout: 600000 alır — Bash tool'un 120 s varsayılanı HEAVY_TIMEOUT'tan kısadır ve komutu daha sırada beklerken öldürürdü. Orijinal komut jq @sh ile tırnaklanır, bileşik komutlar (&&, tırnak içeren) bozulmaz ve sarmalayıcı kabuk $SHELL'dir, sabit bash değil — macOS'un bash 3.2'si $(cat <<'EOF'…) içinde apostrof geçen heredoc'u parse edemez, yani bash -c ile sarmalamak conventional commit mesajlarını sözdizimi hatasıyla düşürürdü. Zaten heavy/lockf/taskpolicy içeren komut es geçilir — komutun yalnız başında değil, komutun başlayabildiği her yerde (cd x && heavy go test dahil), aksi hâlde dış sarmalayıcı iç heavy'nin beklediği slotu tutup kilitlenir. Desenler ~/.config/heavy/patterns.sh ile ezilebilir; eşleşme yoksa çıktı üretilmez (exit 0, passthrough).

Fayda

Guard manuel disipline bağlı değil: hangi projede, hangi oturumda olursa olsun ağır derleme otomatik sıraya girer, dev sunucuları bloklanmaz.

install-heavy.sh
SessionStart

commit

Kod değişikliklerini commit etmeden önce kapsamlı kalite kapısı kurar. Tüm analizi (code-review, test, rules uyumu, Plane issue, Obsidian) sessizce yapar, bulguları biriktirir, tek toplu soru bloğunda sunar, onay sonrası seçilen teslimatı (commit/push/PR/merge) uygular.

Tetikleyici

Akış

Review, arka planda ayrı bir Claude oturumuna devredilir: cd <çalışma-klasörü> && claude --model opus --effort <effort> -p '/code-review <level>' (repo veya worktree kökü). Skill doğrudan çağrılmaz, subagent/Workflow ile koşturulmaz. Seviye diffin karmaşıklığına göre dört kademeden seçilir (varsayılan seviye 3: --effort low + review medium); high+ yalnızca kullanıcı isterse.

Öne çıkan

Code review atlanamaz — "hızlıca commit" dense bile çalışır. Ayrı Claude oturumuna Bash ile devredilir (--model opus, arka planda), effort her zaman medium; high/xhigh/max yalnızca kullanıcı açıkça isterse. Diff birden çok modüle yayılmışsa (tipik durum: issue-workflow yönetici modu — ara commit atılmadığı için tüm iş tek teslimatta gelir) review 3-4 paralel oturuma bölünür: değişen dosyalar örtüşmeyen kümelere ayrılır, her kümeye ayrı oturum, çıktılar birleştirilip dedup edilir. Bulgu düzeltmesi çoksa (>5 bulgu veya 3+ dosya) Workflow ile dosya bazında dağıtılır — yasak review'a aittir, düzeltmeye değil; sonra etkilenen kümeler yeniden review edilir. Bulgular küçük diye filtrelenemez/yumuşatılamaz; uncertain bulgular bile listelenir, false-positive kararını kullanıcı verir. Asla --amend, asla force push, asla git add -A.

Ara build'in ölçmeye çalıştığı bütünlüğü sözleşme fazı önceden sağlar. Ajanlar yalnız kod yazar: test/build/lint/format/git/uygulama başlatma yasak, salt-okuma self-check serbest. Her agent() çağrısında açık model ve effort: sözleşme opus/high, kod-fix opus/medium, mekanik ve salt-okunur iş sonnet/low; haiku yok, fable yasak. Ana agent iş bitene kadar durmaz: tur yalnız üç halde kapanır (iş bitti, sert durak, kullanıcı müdahalesi). Garantisi watchdog döngüsü — Monitor ile nabız izleyici kurulur, her turda .heartbeat tazelenir; 180 sn hareketsizlikte "uyandırma" satırı basılır ve bu bildirim yeni tur açar (üst üste uyarıda bekleme 60→300 sn, nabız dönünce 60). .done yazılınca döngü kapanır. Akış

Stil rehberini oku (yoksa dur) → kanal belirle → bağlam topla → mesaj üret → onay → revize ise yeniden üret + stil dosyasına ders ekle.

Öne çıkan

E-posta kanalı zengin HTML üretir (vurgulu tablo, kalın, liste) ve sistem varsayılan programıyla (open) açıp AskUserQuestion ile onay alır; diğer kanallar düz metin + zed --wait. Stil dosyası tek doğruluk kaynağı (bellekten yazmaz). Revize = öğrenim: her düzeltme kalıcı ders olur. Türkçe karakter ASCII karşılığı (s/sh) yasak.

full-translation
çeviri ajanları: sonnet

Django projesinde tüm dillerin eksik/fuzzy çevirilerini uçtan uca tamamlar — makemessages → po-cli analyze → entry yüküne göre çeviri → apply → compilemessages → commit. po-cli skill tek .po dosyası için; bu skill çok dil × çok domain (django/djangojs/djangof7) matrisini orkestre eder.

Tetikleyici

"tam çeviri akışı", "tüm dilleri çevir", "i18n sync", "translation workflow", /full-translation.

Akış (7 adım)

Repo + mobil pull (koşulsuz zorunlu — mobil HEAD=origin/main doğrulanmadan Adım 1'e geçilmez; atlanırsa F7 metinleri sahte "0 untranslated" verir) → makemessages (3 domain) → po-cli --json analyze → iş birimi = entry sayısı: toplam ≤200 ise inline (Workflow yok), >200 ise dil sınırında ~200'lük chunk'lara bölünüp chunk başına 1 paralel ajan → dry-run validate + tek onay + apply + perl temizlik → compilemessages + re-analyze (yakınsama) → commit skill. Çeviri yoksa bile derle & gönder: hiç untranslated/fuzzy çıkmasa dahi makemessages .po'yu yeniden formatladıysa (line-wrap/header/kaynak konum) compile + commit atlanmaz — .mo tracked ve runtime okunur, .po ile senkron kalmalı. Sadece .po diff'i tamamen boşsa akış temiz sonlanır.

Öne çıkan

Fuzzy msgstr'ye güvenmez (msgid'den sıfırdan), placeholder/slug/marka kuralları ajan prompt'una gömülü, plural (nplurals) tablosu dile göre. po-cli'yi tekrar etmez, ona dayanır. Kapalı diller çevrilmez: HIDDEN_LANGUAGES (örn. djangomain/app_options.py) dinamik tespit edilir, analiz + çeviri + yakınsama matrisinden çıkarılır — kapalı dile token harcanmaz, "tüm diller temiz" kriteri hidden hariç değerlendirilir.

web-scrape-cleaner
model: haiku

Ham scrape markdown'ındaki gürültüyü temizler (nav/footer/cookie banner/reklam, boş başlık, link gürültüsü). Maliyet-optimize haiku modelinde çalışır. Tools: Read/Edit/Write/Glob/Grep/Bash.

Nasıl çalışır

Keşif (örnek dosyada gürültü tespit) → tüm dosyaları concat + uniq -c ile 5+ dosyada tekrar eden satırları sil → aggressive/conservative temizleme → fark >%5 ise üstüne yaz (orijinal silinmez) → başlık hiyerarşisi + link sadeleştirme.

Öne çıkan

Asla scrape etmez (sadece mevcut .md düzenler), asla git commit yapmaz, KEEP listesine dokunmaz. İstenirse .original/ yedeği bırakır.

Bağımlılıklar · dış araçlar

Plugin neye dayanıyor?

Plugin kendi başına çalışır, ama tam gücü dış araçlarla entegrasyonundan gelir. setup.sh hepsini tek komutla kurar; her araç opsiyoneldir — yoksa ilgili özellik sessizce devre dışı kalır.

setup.sh + setup.py
Tek komutla kurulum

Tüm stack'i tek komutla kuran idempotent installer. setup.sh önce uv yoksa kurar, sonra setup.py'yi rich/questionary bağımlılıklarıyla ephemeral venv'de çalıştırır (global kirletmeden).

Ne kurar

settings.json + statusline, Homebrew prerequisites, Python CLI araçları (uv tool), Obsidian vault + CLI, local MCP repo'ları, plane-cli, po-cli, Playwright CLI, playwright-best-practices skill'i, Context7 CLI, Claude Code MCP server'ları ve interaktif credential prompt'ları.

Çalıştırma
./setup.sh              # uv kurup başlatır
# idempotent — tekrar çalıştırılabilir, mevcut olanı atlar
Obsidian
vault · bilgi tabanı

Nedir: Markdown tabanlı yerel bilgi tabanı; dosyalar [[wikilink]] ile birbirine bağlanır. Vault düz dosya sistemidir — uygulama açık olmadan da okunur/yazılır. Resmi CLI (obsidian komutu) BM25 arama ekler, zorunlu değildir.

Ne işe yarar: Kalıcı teknik gerçeği (sistem davranışı, kalıcı karar, credential) oturumlar arası taşır. Genel alan klasörleri tüm projeleri besler; proje klasörü yalnız kendine özgü olanı tutar.

Plugin'deki rolü

Plugin'in kalbi. 3 skill (obsidian-search/obsidian-write/obsidian-doc-source) doğrudan Obsidian üzerine kurulu — hepsi ana agent context'inde çalışır, subagent yoktur. userprompt-obsidian-hint.sh her non-trivial prompt'ta arama+yazma davranışını hatırlatır. Vault ~/Documents/ObsidianVault/ altında klasör hiyerarşisidir (genel alan + proje); MOC/index.md kullanılmaz. Erişim Glob/Grep/Read ile, Obsidian CLI opsiyonel.

Solo
CLI · process yönetimi

Nedir: Geliştirme process'lerini (backend, frontend, worker vb.) yöneten bir araç; solo.yml ile tanımlanan komutları başlatır, durdurur, yeniden başlatır ve çıktılarını takip eder. solo CLI binary'si Solo app'in HTTP control plane'ine bağlanır (solo doctor ile doğrulanır).

Ne işe yarar: Tekrar eden shell komutlarını (build + run) tek yerde toplayıp Claude'un bunları başlatıp loglarını okumasını sağlar.

Plugin'deki rolü

soloterm.md kuralı: tekrar eden komutlar için mutlaka solo.yml oluşturulur ve komutlar Solo üzerinden çalıştırılır. Process başlatma/durdurma/restart solo processes / solo commands CLI komutlarıyla yapılır; process çıktısı/logu artık solo processes output ile CLI'den okunur (v0.8+; --lines/--raw destekli) — eski GUI/log-dosyası workaround'ı ve geçici Solo MCP yara bandı kaldırıldı. (Bu plugin repo'sunda tek process var: render — PA Render server.)

PA Render
Bun server · canlı analiz dashboard'u

Nedir: scripts/render-server.ts — Bun ile yazılmış sıfır-bağımlılık HTTP server (127.0.0.1:4787). ~/.pa-render/active|archive/<konu>/index.html sayfalarını tek ekranlı dashboard'da sunar: sol sidebar (aktif + katlanabilir arşiv listesi, görülmemiş-değişiklik dot'u), ortada iframe, SSE ile auto-reload — agent dosyayı Edit'leyince ekran kendini tazeler. Sayfa üstündeki topbar'da arşivle/geri al butonu ve ekler (N) anahtarı; sağda Dosyalar paneli konu klasöründeki tüm ek dosyaları (ekran görüntüsü, JSON, diff, log) listeler — tıklayınca dosya aynı ekranda açılır, Cmd/Ctrl+tık yeni sekmede (/api/files).

Kanıt viewer'ı (/view/…): görsel/HTML dışındaki dosyalar ham metin yerine biçimli açılır — JSON katlanabilir renkli ağaç, log seviye renkleri (error/warn/info/debug) + seviye çipleri + satır filtresi, diff/patch +/− ve hunk renklendirmesi (içerikten otomatik algılanır), düz metin satır numaralı. Her modda satır no, wrap anahtarı, panoya kopyala ve ham dosya bağlantısı var; 20.000 satır üstü kesilir.

UI kit: render/lib/ — pa.css design system (çift tema, B-section kartları, badge/callout/tablo/oq/risk) + pa.js web component'leri (pa-flow, pa-step, pa-leg, pa-compare, pa-kpi, pa-timeline) + vendored Chart.js ve preact/htm. Sayfalar /lib/*'ı link'ler — inline CSS yok. .jsx dosyaları istekte anında transpile edilir.

Plugin'deki rolü

user-render skill'inin sunum katmanı. Solo process render ile başlatılır (solo.yml); arşivle/geri-al hem UI butonlarıyla hem /api/archive endpoint'iyle yapılır. Agent server'ı hiç bilmez — yalnız dosya yazar.
